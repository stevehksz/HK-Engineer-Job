# 校验与代码修复方法论

本 Skill 只维护能够通过修改小程序代码、配置或本地确定性优化解决的问题。微信授权、账号、频率、审核、备案、主体、类目和平台资格错误以 Genie BaaS 返回的权威分类、用户文案和下一步为准，不在这里复制错误码解释。

## 开发阶段：先避免和修复确定问题

- JSON、工程根、`pages`、`tabBar`、本地引用、WXML/WXSS/WXS 和 npm 依赖问题，按 WorkBuddy 本地 daemon 的原生校验结果定位并修复。
- 本地 daemon 可以按现有确定性规则优化 JSON、`miniprogramRoot`、转译和构建兼容问题；必须记录优化动作并重跑对应校验。
- 需要理解业务语义的修改由 Agent 完成。不能把预览成功说成原生编译或发布成功。

## 发布阶段：只处理代码可修复错误

Genie BaaS 返回微信错误后，只有被权威结果分类为代码或配置问题时，才使用本 Skill 的方法论继续修复：

- WXML/WXSS/WXS 编译错误：根据文件、行列和编译信息修改代码。
- JSON、`pages`、`tabBar.pagePath` 或路径错误：修正对应配置和本地引用。
- 代码包超限：优化资源、删除无用依赖或合理拆分分包，不删除用户需要的业务能力。
- `requiredPrivateInfos` 名称或互斥组合错误：按代码实际使用的隐私 API 修正配置。
- 插件版本格式或明确的版本配置错误：修改 `app.json` 中的插件版本后重新校验。

修复后重新执行本地校验，再走既有发布流程。若 Genie BaaS 将错误分类为授权或平台限制，原样采用其用户文案，不猜测代码修复方案，也不新增独立的错误事件或会话回放机制。
