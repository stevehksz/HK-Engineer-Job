# 互联网网页开发专家团（internet-web-expert）

面向网页与小程序的全链路开发专家团：从需求分诊、界面设计、前端实现、云端后端，到发布上线与线上核验，一条流水线走完。

## 类型

Team 型（多角色协作团队）

## 整合的 WorkBuddy 能力

本专家包把 WorkBuddy 的既有能力与实战经验打进了同一个包里，无需另外安装：

| 技能 | 来源 | 作用 |
|------|------|------|
| `web-cloud-service` | WorkBuddy 内置 | 云数据库、用户认证、文件存储、免密钥 LLM 调用 |
| `web-miniprogram-development` | WorkBuddy 内置 | 微信小程序原生工程、开发者工具编译、托管发布 |
| `web-publish-sites` | WorkBuddy 内置 | 站点发布为在线链接、下架、应用卡注册 |
| `web-single-file-fusion` | 实战沉淀 | 独立单文件 HTML 工具融进多页面平台的方法论 |
| `web-release-pipeline` | 实战沉淀 | 改版→静态校验→发布→线上核验流水线与踩坑清单 |

后两项来自真实项目的实战记录，包含 CDN 缓存导致线上拿到旧版、Origin 白名单导致 403、
云端 SDK 失效时同源 REST 兜底、jsdom 全链路调试与三场景回归、无头浏览器截图目视等
已验证有效的处理方式，可直接复用。

> 技能内的私有标识（应用 ID、密钥、账号、仓库名、本机路径）已全部替换为占位符，
> 方法论部分完整保留。使用时按自己的实际环境填入即可。

## 典型场景

- 从零做一个网站：需求分诊 → 界面设计 + 前端实现并行 → 云端数据模型 → 发布 → 线上核验
- 已有平台改版：读现有代码 → 定位根因 → 融合新板块 → 静态校验 → 发布验证
- 界面审查：配色排版、移动优先适配、WCAG 2.2 对比度与键盘可达性检查
- 微信小程序：原生工程搭建、云服务接入、真机预览、托管发布
- 线上问题排查：发布成功但线上不对、线上仍是旧版、表单提交失败

## 使用示例

- 帮我做一个网站，从界面设计、前端实现、云端数据库到上线发布一条龙做完。
- 审查一下这个网页的界面和无障碍问题，给我一个移动优先的改造方案。
- 这个页面点击没反应，手机上显示还不对，帮我查出根因并修好。

## 安装

专家包目录位于：

```
C:\Users\Administrator\.workbuddy\plugins\marketplaces\my-experts\plugins\internet-web-expert\
```

注册命令使其在专家中心可见：

```bash
python3 scripts/register_expert.py <expert-dir>
```

## 打包分享

```bash
python3 scripts/package_expert.py <expert-dir>
```
